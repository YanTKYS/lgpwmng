# ストア掲載文案（日本語）

Chrome ウェブストア Developer Dashboard → **Store listing** タブへ入力する内容の案です。
言語は「日本語」を選択します。

掲載文では「完全に安全」「絶対に漏洩しない」「100% secure」のような保証表現を使いません。
実装している事実だけを記載しています。

---

## Name（名前）

```text
lgpwmng
```

`manifest.json` の `name` と一致させます。上限は 75 文字ですが、短い名前のままにします。

副題（`lgpwmng - ログイン入力補助` のような形式）は付けません。ストア上の一覧では
Short description が併記されるため、名前を長くする必要がないためです。

## Short description（概要）

上限 132 文字。`manifest.json` の `description` と同一にします（Dashboard には manifest の
`description` が初期値として入ります）。

```text
業務システムのログイン入力補助。任意の入力項目と複数アカウントに対応。認証情報は端末内に暗号化して保存し、外部通信は行いません。
```

（64 文字）

## Category（カテゴリ）

```text
Make Chrome yours → Privacy & Security
```

公式ドキュメントのカテゴリ定義が
「Privacy & Security: Extensions such as VPNs, **password safes**, and phishing deterrence.」と
password safe を明示しているため、こちらを第一候補とします。

代替として `Productivity → Workflow & Planning`
（「Extensions to help users perform their tasks more efficiently」）も妥当です。
入力作業の効率化という側面を前面に出す場合はこちらを選びます。

いずれを選んでも審査基準は変わりません。申請時にどちらを前面に出すかで決めてください
（カテゴリは Dashboard 上でいつでも変更できます）。

## Detailed description（詳細な説明）

```text
lgpwmng は、業務システムのログイン画面へ、あらかじめ端末内に登録しておいた認証情報を入力する
ための拡張機能です。ログインボタンの自動押下は行わず、送信は利用者が行います。

■ こんな画面のための拡張です

自治体をはじめとする組織の業務システムでは、ID とパスワードだけでなく、自治体コード・団体コード・
所属コード・職員番号・第二パスワード・PIN といった入力欄が並ぶログイン画面が珍しくありません。
同じドメインでもパスごとに別のシステムであったり、1 つのシステムを通常業務用と管理者用の
アカウントで使い分けたりすることもあります。
ブラウザ標準のパスワード管理はこうした画面を想定していないため、一部の欄しか入力されない、
アカウントを取り違える、といったことが起こります。

lgpwmng は、サービスごとに任意の入力項目を定義し、登録済みの値をまとめて入力します。

■ 主な機能

・任意の入力項目に対応
  ID とパスワードの 2 項目に限りません。自治体コード・所属コード・職員番号・第二パスワードなど、
  そのログイン画面にある入力欄を必要なだけ登録できます。項目を増やすために設定ファイルを
  書き換える必要はありません。

・ログイン画面から登録
  対象のログイン画面を開いて拡張アイコンを押し、「このログイン画面を設定」を選ぶと、
  ページ上の入力欄が一覧表示されます。表示名と区分を確認して保存するだけで登録できます。

・複数アカウント
  1 つのサービスに、名前を付けた複数のアカウントを登録できます。自治体コードのように
  アカウント間で共通の値は「サービス共通値」として 1 か所で管理できます。

・管理者アカウントの確認
  管理者区分のアカウントは既定では選択されず、選ぶと確認のチェックが必要になります。
  一覧では管理者バッジと警告色を表示し、取り違えを防ぎます。

・frame / iframe への対応
  frameset / frame を使った画面や、iframe にログインフォームを埋め込んだ画面にも対応します。
  同じ推定名の入力欄が複数のフレームにある場合は自動確定せず、利用者が選びます。

・URL 条件による照合
  サービスの判定はオリジン（プロトコル + ホスト名 + ポート）とパスで行います。http と https、
  ポート違いは別のものとして扱います。入力の直前にも URL を再確認し、条件に一致しない場合は
  1 項目も入力しません。

・暗号化して端末内に保存
  登録データ全体を、マスターパスワードから導出した鍵で暗号化して保存します
  （PBKDF2-SHA256 310,000 回 + AES-GCM 256bit、いずれもブラウザの Web Crypto API）。
  マスターパスワード自体は保存しません。ブラウザを再起動すると必ずロック状態に戻ります。

・外部通信なし
  外部 API・CDN・クラウド同期・分析・広告・テレメトリのいずれも使用しません。
  ネットワーク通信を行うコードを含んでおらず、閉域ネットワークの端末でも動作します。

・バックアップ
  暗号化されたバックアップファイルを出力し、別の端末へ復元できます。
  パスフレーズはマスターパスワードとは独立に指定します。

・選択したアカウントの共有
  選んだアカウントだけを暗号化ファイルとして出力し、別の端末の lgpwmng へ取り込めます。
  取り込みは追加・更新のみで、受け取った側の他のサービス・アカウントは維持されます。
  自動送信・自動同期は行いません。ファイルの受け渡しは利用者が行います。

・自動ログインしない
  ログインボタンを自動で押すことはありません。入力後の内容を確認し、利用者自身がログイン操作を
  行います。ページを常時監視する常駐スクリプトもありません。

■ 権限

activeTab / scripting / storage の 3 つだけを使用します。<all_urls> のような広範な権限は
要求しません。ページへのアクセスは、利用者が拡張アイコンを押したときに限られます。

■ 動作確認用のデモページ

対象となる業務システムは組織内にあるため、動作を試せる公開デモページを用意しています。
https://yantkys.github.io/lgpwmng/reviewer-demo.html

■ 注意

・マスターパスワードは保存されません。忘れると登録済みの認証情報を復元できません。
・端末の管理が前提です。OS アカウントを共有している端末での利用は避けてください。
・Shadow DOM 内の入力欄、画面遷移型（ID 入力の次画面でパスワード）のログインには対応していません。

■ プライバシーポリシー

https://yantkys.github.io/lgpwmng/privacy.html

■ ソースコード

https://github.com/YanTKYS/lgpwmng
```

## 使用しない表現

審査・掲載時に誤解を招くため、次のような表現は使いません。

| 使わない表現 | 代わりに書く事実 |
| --- | --- |
| 完全に安全 / 絶対に漏洩しない / 100% secure | 「PBKDF2 + AES-GCM で暗号化して端末内に保存します」 |
| 最強のパスワード管理 / No.1 | 機能の説明のみ |
| ハッキング不可能 / 破られない | 使用しているアルゴリズムと保存場所の説明のみ |
| 自治体専用 | 「自治体をはじめとする組織の業務システム」（利用対象を限定する表現にしない） |
| 自動でログインします | 「ログインボタンの自動押下は行いません」 |
