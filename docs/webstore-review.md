# 審査用テスト手順（Chrome ウェブストア審査担当者向け）

このページの英語版・要約版は [webstore/reviewer-notes.md](webstore/reviewer-notes.md) にあります。
Developer Dashboard の審査コメント欄には、そちらの短い版を貼り付けてください。

---

## 0. 前提

lgpwmng は、自治体をはじめとする組織の業務システムのログイン画面に、利用者が端末内へ登録した
認証情報を入力するための拡張機能です。対象となる業務システムは閉域ネットワーク内にあり、
審査担当者がアクセスすることはできません。そのため、**動作確認用の公開デモページ**を用意しています。

| 項目 | URL |
| --- | --- |
| Reviewer Demo（標準版・基本ケース） | <https://yantkys.github.io/lgpwmng/reviewer-demo.html> |
| Reviewer Demo（iframe 版・追加ケース） | <https://yantkys.github.io/lgpwmng/reviewer-demo-frame.html> |
| Privacy Policy | <https://yantkys.github.io/lgpwmng/privacy.html> |

デモページは架空の業務システムを模したものです。実在する組織名・ドメイン・認証情報は使用していません。
「ログイン」ボタンを押しても認証は行われず、どこへも送信されません。

### デモ用ダミー認証情報

実在する認証情報ではありません。任意の値でも動作を確認できます。

```text
自治体コード: 123456
ユーザーID:   test-user
パスワード:   test-pass-123
```

マスターパスワードは審査担当者が任意に決めてください（8 文字以上。例: `review-test-1234`）。
拡張はマスターパスワードを保存せず、外部へも送信しません。

## 1. 基本ケース（frame / iframe なし）

1. **Reviewer Demo ページを開く** — <https://yantkys.github.io/lgpwmng/reviewer-demo.html>
2. **lgpwmng のアイコンをクリックする。**
3. 初回のみ **「lgpwmng のデータ利用について」** が表示される。扱う情報（現在のページの URL、
   入力欄の情報、入力済みの値）と、外部送信しないことが示される。
   **「同意して利用を開始」** を押す。
   - この同意より前に、拡張は現在のタブの URL を取得しません（`chrome.tabs.query()` を呼びません）。
     ページへのコード注入も行いません。DevTools で確認できます（4. を参照）。
   - 同意は `chrome.storage.local` に開示バージョンだけを記録します。2 回目以降は表示されません。
4. 続けて **マスターパスワード設定画面**が表示される。8 文字以上の任意の値を 2 回入力し、
   「設定する」を押す。
   （2 回目以降は「アンロック」画面が表示されるので、同じ値を入力する。）
5. popup に「未登録のログイン画面」と表示される。**「このログイン画面を設定」** を選択する。
6. 「ログイン画面の設定」タブが開き、ページ上の入力欄が候補として一覧表示される。
   自治体コード / ユーザーID / パスワードの 3 行について、次を確認する。
   - 「使用」にチェックが入っている
   - 「表示名」が推定されている（自治体コード / ユーザーID / パスワード）
   - 「対象入力欄」がそれぞれの入力欄を指している
   - 各行の「確認」を押すと、対象の入力欄がページ上で一瞬強調表示される
7. 画面下部の「アカウント」で、**ダミー値**を入力する。
   - 自治体コード: `123456`（「区分」が「共通」の場合はサービス共通値の欄に入力する）
   - ユーザーID: `test-user`
   - パスワード: `test-pass-123`（秘密項目のためマスク表示。「表示」で確認できる）
8. **「保存」** を押す。「保存しました」と表示される。
9. **Reviewer Demo のタブへ戻り、再読み込みする**（入力欄が空になる）。
10. **lgpwmng のアイコンをクリックする。** 登録したサービス名とアカウント一覧が表示される。
11. アカウントを選び、**「ログイン情報を入力」** を押す。
12. **確認事項**
    - 3 つの入力欄へ、登録したダミー値が入力される。
    - **ログインボタンは自動で押されない**（画面遷移も送信も発生しない）。送信は利用者が行う。
    - popup を開いたまま別のページへ遷移してから入力を実行した場合、URL 条件に一致しないため
      **1 項目も入力されない**。

## 2. 追加ケース（iframe 内のログインフォーム）

frame / iframe に埋め込まれたログインフォームへの対応を確認する場合のみ実施してください。

1. <https://yantkys.github.io/lgpwmng/reviewer-demo-frame.html> を開く。
2. 1. と同じ手順（アイコン →「このログイン画面を設定」→ 登録 → 保存 → 再読み込み → 入力）を行う。
3. 設定画面の候補一覧で、フレーム内の入力欄に `[フレーム: ...]` の補足が付くことを確認する。
4. 入力実行時に、iframe 内のフォームへ値が入ることを確認する。

## 3. 権限が使われる場面

| 権限 | いつ使われるか |
| --- | --- |
| `activeTab` | 手順 5（「このログイン画面を設定」）と手順 11（「ログイン情報を入力」）で、利用者が操作した現在のタブに対してのみ。いずれも手順 3 の同意より後 |
| `scripting` | 同上。`chrome.scripting.executeScript` で走査 / 入力コードを注入する。常駐 content script は登録しない |
| `storage` | 手順 3 の同意記録、手順 8 の保存、および手順 4 のアンロック状態の保持 |

拡張アイコンを押していない間、拡張はページに一切アクセスしません。
**手順 3 の同意より前は、現在のタブの URL も取得しません。**

## 4. 外部通信がないことの確認方法

1. DevTools を開き、Network タブを表示した状態で上記の手順を実行する。
2. 拡張由来のリクエストが発生しないことを確認する（デモページ自身の読み込みを除く）。
3. Service Worker（`chrome://extensions` →「Service Worker」）の DevTools でも同様に確認できる。
4. 同意前にページへ触れないことは、拡張を入れ直した直後（未同意の状態）に popup を開き、
   対象ページの DevTools でコード注入が起きないことを確認すると分かる。

拡張のコードには `fetch` / `XMLHttpRequest` / `WebSocket` / `EventSource` /
`navigator.sendBeacon` の呼び出しがありません。`manifest.json` に `host_permissions` はなく、
CSP は `script-src 'self'; object-src 'self'` です。リモートホストのコードは実行しません。

## 5. その他の機能を確認する場合

いずれも popup →「サービス一覧」（options ページ）から確認できます。

| 機能 | 場所 | 確認内容 |
| --- | --- | --- |
| サービス／アカウント管理 | 「サービス」タブ | 手順 7 で登録した内容の編集、アカウントの追加・削除 |
| マスターパスワード変更 | 「マスターパスワード / バックアップ」タブ | 変更後も登録データが読めること |
| バックアップ | 同上 | パスフレーズを入力してエクスポート。暗号化された JSON が端末へ保存されるだけで、送信は行われない |
| アカウント共有 | 同上「アカウント共有」 | 選択したアカウントだけを暗号化ファイルとして出力。自動送信は行わない |

出力されるファイルはいずれも AES-GCM で暗号化されており、平文の認証情報を含みません。

## 6. 想定される確認ポイントへの回答

| 論点 | 回答 |
| --- | --- |
| Single purpose | 業務システムのログインフォームに、利用者が端末内へ登録した認証情報を安全に入力するためのログイン入力補助ツール。詳細は [webstore/single-purpose.md](webstore/single-purpose.md) |
| Remote code | 使用していません（`No, I am not using remote code`）。詳細は [webstore/remote-code.md](webstore/remote-code.md) |
| 収集したデータの送信先 | 送信しません。すべて端末内（`chrome.storage`）に保存します |
| 認証情報の保護 | PBKDF2-SHA256（310,000 回）で導出した鍵による AES-GCM 256bit 暗号化。マスターパスワードは保存しません |
| 自動ログイン | 行いません。ログインボタンの押下は常に利用者の操作です |
| 広範なホスト権限 | 要求しません。`activeTab` のみで、利用者の操作時に限りページへアクセスします |
| 目立つ開示と明示的な同意 | 初回起動時に popup で扱う情報・用途・外部送信しないことを示し、同意を得るまで URL 取得もコード注入も行いません。詳細は [webstore/privacy-practices.md](webstore/privacy-practices.md) の 4.5 |
